## 2. Corrections to earlier claims — read this before trusting older commit messages

Several things I asserted during the run turned out wrong and were corrected in later commits. If you
read only the earlier message, you will be misled.

1. **RT-04 cold load is not reachable from `clozn serve`.** I first said it was "latent until RT-05
   removed the global gate". Wrong cause. `ProjectionFileRouter` had no `loader=` parameter and
   `app.py` never passed one. A seam now exists; the remainder is blocked by a **process boundary**
   (§4).
2. **RT-04's eviction in-flight safety is vacuous.** I claimed it "consults REAL in-flight state via
   `WorkerHandle.track_call`". Eviction *consults* `handle.busy`, but nothing in production ever
   *enters* `track_call`, so every worker always looks idle. Fix in flight at writing.
3. **The "worker protocol has no request id" cancellation claim is overstated.** A worker-minted
   request id exists and *is* cancellable via `POST /cancel` — but only for the single active
   generation stream, not score/harvest/intervene/checkpoint or a cold load's spawn+handshake, and the
   token lives in gateway memory unreachable from the supervisor. The limitation survives; the stated
   reason was wrong.
4. **The task-specificity result is a bounded negative, not "inconclusive".** I read a
   `k_min_detected: null` as a power ceiling. It was the output of a **misspecified permutation null**
   built from only hit-bearing disagreements. After two fixes the test has demonstrated power
   (MDE 5/14 = 35.7%).

## 3. Research results

**Population study (n=30, controlled).** Q2_K disagrees with Q8_0 on 84.9% of prompts / 23.8% of 2384
scored positions; Q4_K_M on 42.6% / 7.7%. `structured_json` is by far the most robust category
(40.0% / 6.2%) — constrained low-entropy output survives quantization far better than free-form.
MLP-path bisects beat the random control in 20/30 cases, attention in 6/30. Depth gradient monotonic:
early 20.6% / mid 33.2% / late 53.1%.

**Mixed-precision bands (the headline).** Late-MLP band transplants restore **60%** of live
disagreements; matched early **20%**, mid **16%**. The paired comparison carries the claim, not the
marginal rates: **10 disagreements where late restored and early did not, 0 the other way; 12 vs 1
against mid.** Random equal-norm at the late band restored **0/25**.

*External corroboration* — the reason this outranked other research items: llama.cpp's own
`use_more_bits` already upgrades Q4_K_M's `ffn_down` to Q6_K at layers
{0,1,2,5,8,11,14,17,20,23,24,25,26,27}, while Q2_K's `ffn_down` is uniformly Q3_K with no depth
variation. Q4_K_M protects several late ffn layers and disagrees on 42.6% of prompts; Q2_K protects
none and disagrees on 84.9%. The shipped quantizer heuristics already encode something like this.

*Ceiling, stated in the doc:* transplanting exact reference activations is an **upper bound** on what
mixed-precision quantization could recover — not the same as quantizing those layers differently.

**Task specificity (bounded negative).** No layer restores one capability but not another:
`max_purity` p=0.336, `chi2_sum` p=0.352, bounded by a demonstrated 35.7% detection floor. So the
population study's task-independence reading — the reason late-layer recurrence looks like quantizer
geometry rather than circuitry — is **plausible but not statistically established** at the available n,
and is now qualified in that doc.

## 4. Open risks and blocked work

* **Cross-process cold load** — `docs/design/006-cross-process-cold-load-protocol.md` is the decision
  record. The gateway is a separate OS process from the supervisor that owns worker lifecycle; a loader
  in the gateway must either import `clozn.cli` into `clozn.server` (forbidden) or run a second,
  disconnected registry that spawns duplicate workers. **Do not wire cold load without also fixing the
  eviction vacuity** — an unreachable feature is a nuisance; a reachable one that evicts mid-generation
  corrupts a run.
* **Managed-mode surfaces fail closed for every run**, not just edge cases: receipts, replay,
  influence, and legacy fork all call plain `active_sub(h)`, which returns `None` under a managed
  gateway. Only execution-fork and snapshot pin resolve the model per run.
* **`/v1/completions` retirement** — never done, compatibility route still live.
* **Pre-existing branch/worktree backlog** — `feat/batched-sweep` (2 ahead),
  `feat/platform-macos-linux` (1), and six `worktree-agent-*` branches (1–16 ahead). **Not triaged, not
  deleted — this needs a human decision.** Merging a 342-commit-stale branch already cost real work
  this run when its premise had moved underneath it.
* `notes/UX_INFORMATION_ARCHITECTURE.md` §7.6 (casting spec) remains unimplemented in the React Studio.
* `docs/PRODUCT_ROADMAP.md` still carries two overlapping status headers.

## 6. Process lessons worth keeping

* **An unexpectedly good result is the best evidence the instrument is broken.** One result was
  retracted mid-run when all 87 random-control arms turned out to share a single frozen direction
  (`random.Random(seed)` constructed fresh per call is not independent sampling across calls). It was
  caught only because the number beat a hard-won prior.
* **Writing user documentation is a verification technique.** An agent tasked with "here is how you use
  this" traced the real end-to-end path and found that RT-04 was unreachable — something two
  implementing agents had missed.
* **Removing a lock exposes what it was hiding.** Deleting the global POST gate surfaced a 5–12%
  race in run-store schema init. Root cause was not the migration DDL but `PRAGMA journal_mode=WAL`,
  a one-time on-disk format conversion that concurrent first-time openers race.
* **Flake-hunt every concurrency test.** At a 5–12% base rate, a single green run proves nothing. The
  bar used here was 25+ consecutive runs; one test was validated over 1500 request executions.
* **Agents declining part of a brief was right four times** — RT-05 refusing per-worker parallelism
  because `EngineSubstrate` holds shared per-instance state; the RT-04 agent refusing to cross the
  server/cli boundary; and two research agents correcting their own statistics before reporting.
  A spec written from outside the code does not always survive contact with it.
* **Long GPU runs outlive the agent that starts them and then die orphaned.** Four runs hit this.
  Aggressive per-item checkpointing plus an external watch on the checkpoint file is what makes it a
  non-event.
